# CLAUDE.md

## Project Overview

atmina is a Latvian political transparency platform. Scrapes news sources + Twitter/X profiles (via twikit), extracts pozīcijas (claims) and pretrunas (contradictions) per politician, renders an interactive HTML site. Tracks politicians across multiple parties. Primary language: Latvian (lv), some Russian (ru). No sentiment analysis — removed as unreliable.

**This file is the operating manual.** It is written so a session with no other context (no private memory, no prior conversation) can work here safely. Section numbers below (Data Contract #N, inv #N) are referenced from tests, `wiki/CHANGELOG.md`, and agent prompts — never renumber them. This file syncs to the PUBLIC mirror: keep it free of operator-identifying or internal-only detail.

## Standing Decisions (operator-set; do not re-litigate)

- **Public anonymity.** atmina.lv publishes anonymously. Never add operator-identifying information (personal names, company names, e-mail addresses) to any public surface — the site, the public mirror, social posts, commit text, or repo docs. The public mirror is rebuilt from this repo minus a fixed exclusion set (maintainer note, private): **assume any new file is public unless its directory is in that set.**
- **Timing.** Ingest runs all day; claim extraction + daily brief only in the afternoon (~15:00 LV or later). A morning "0/N analyzed" is the expected state, not a failure.
- **Subagent model = Opus, both directions.** ALL project agents in `.claude/agents/` carry `model: opus` in frontmatter (since 2026-07-21). Downward bound: a smaller-model trial (2026-06-11) produced LV grammar errors in ~30–40% of stances and was rejected. Upward bound: subagents must NOT inherit a Mythos-tier session model (Fable) — Opus is sufficient and the cost difference is not justified (operator decision 2026-07-21). Workflow `agent()` calls must pass `model: 'opus'` explicitly (frontmatter pins don't reach plain `agentType: 'general-purpose'` calls). Orchestration (the main loop) may run on any tier. **2026-08-10 supervised exception (not a rule change):** the operator ran one full daily extraction on DeepSeek subagents (57/57 politicians, 67 claims) with heavy orchestrator QA — it worked, but QA caught semantic defects lint cannot see (title fabrication, verb-strength upgrades, RT-with-verbatim-quote class; CHANGELOG 2026-08-10 (1)). The Opus floor is unchanged as the default for unattended `.claude/agents/` runs.
- **Publish pause.** Nothing outward-facing auto-publishes. Daily/weekly brief → manual proofread + featured-image confirm + explicit operator approval BEFORE deploy. Approval for one publish is never standing approval for the next.
- **Syntheses are hand-written.** `wiki/synthesis/` pages are manually authored (standing decision 2026-04-22). Do not propose an auto-synthesis agent.
- **Deploy is additive.** `bash scripts/deploy.sh` (additive is the default since 2026-08-01; `--no-delete` is still accepted and every runbook passes it). `finanses` + `statistika` remote dirs are curated — never delete remote trees. `--delete` exists but is only ever correct after a FULL render.
- **Rules live in the repo, not private memory.** Any decision future sessions must honor goes into this file, a wiki runbook, or an agent prompt — subagents, cloud runs, and fresh sessions cannot see private memory.

## Working Conventions

- **Silent success is a defect class.** The load-bearing stores can discard input while returning success: `save_analysis()` reports drops only in its returned `failures` list (stderr, easy to miss). Always inspect returned failure structures and verify stored-count == intended-count. Any new operation that can drop input must report what it dropped. Within one call the idempotency merge is now reported (`silent_dedup` entry, `status="partial"` — `tests/test_silent_dedup.py`); a collision with a claim stored in an EARLIER call is still silent — that is what stored-count == intended-count catches.
- **A gate that cannot fail is not evidence — report the denominator, not just the finding.** Every check, lint, audit and status step states *how many things it examined*; a denominator of 0 or 1 is a broken gate, not a clean result. A green all-clear stops people looking — reference: `/audit-integrity` check 7 scanned a deployed directory holding exactly one file and reported clean for months while two published briefs carried a 404 hero (2026-08-02; more in [CHANGELOG](wiki/CHANGELOG.md)). Corollaries: **(a)** a checker's tests must assert it reads what the writer actually writes (pattern: `tests/test_wiki_lint.py::test_lint_reads_keys_wiki_sync_actually_writes`); **(b)** a number in `BACKLOG.md`/`CHANGELOG.md` is trustworthy only with the query that produced it; **(c)** **"IZPILDĪTS" means the code is in the tree, not that it ever ran.** When a fix changes behaviour on a path that fires less often than daily (Saeima ingest, deploy, public sync), record *what exercised it* — a test, a live run, or nothing. If nothing, write the gate; don't wait for the event. Both 2026-08-21 resource verdicts sat merged-but-never-executed for a day under an IZPILDĪTS heading (`tests/test_saeima_resource_verdicts.py` closed it; CHANGELOG 2026-08-22 (3)). A gate is only proven when you have seen it FAIL — mutation-test it by reverting the fix.
- **Write through the `store_*()` functions — a raw INSERT silently drops their guardrails.** The validation lives in the function, not in the schema. `store_tension()` refuses a `source_url` absent from `documents`; `store_claim()` normalizes topics and embeds (`saeima_vote` excluded since 2026-08-21 — vote claims carry no vector by verdict); `save_analysis()` is transactional. If a store function refuses your row, the row is wrong; do not route around it. `/audit-integrity` check 10 detects the bypass after the fact (2026-07-29: a raw-INSERT tension citing a nonexistent status ID reached a published brief).
- **Denormalized fields are stale by default.** `tracked_politicians.party`, `role`, and `claims.topic`-vs-`votes.topic` do not auto-sync from the news. When claim content implies a party/office change, verify against the truth source and apply a manual UPDATE with a paired rollback.
- **Short generated name forms are quarantined.** Matcher-generated inflected forms ≤4 chars are substring bombs ("Kolu" → "Kolumbija"). Flag them for operator review; never auto-add `name_forms` or `negative_patterns` — those are operator-review changes by standing rule.
- **Stop beats write.** When two rules could apply and you cannot tell which, choose the action that stops-and-surfaces over the one that writes. Silent writes are the expensive failure here; stopping is cheap.
- **Deleting a claim does NOT remove its source document from the site.** Two independent surfaces carry the same text: the claim (politician page positions, brief, coverage — all gated on `claim_type='position'`) and the raw document (the profile's X subtab renders the politician's last 50 `role='subject'` tweets straight from `documents`, no suppression flag — `src/render/politicians.py`). Removing a position is an editorial act about atmina's own assertion; the feed item is a mirror of the person's public post. When a claim is withdrawn because its CONTENT is unsound, decide explicitly whether the document should also go, and say which surface you actually cleared — "claim deleted" is not "content removed".
- **Abstention blocks — the label differs, the effect does not.** A Saeima motion carries on a majority of those present, and `Atturas` counts toward presence. So an abstention denies the majority exactly as a `Pret` does: the proposal falls either way. Treat `Atturas` as a substantive act, never as neutrality or absence — "atturējās" in a stance line means the deputy helped defeat the motion (operator ruling 2026-07-25). Two things this does NOT license: (a) writing that someone "balsoja pret" when the record says `Atturas` — state the ballot as recorded; (b) reading a single procedural abstention as a policy position — see T14.

## Data Contracts

1. **TOMBSTONE (2026-07-29).** Šeit stāvēja `oppo_briefs` JSON-kolonnu konvencija. Tabula (politracker mantojums, 0 rindu kopš 2026-04-06 pivota) un tās vienīgais lasītājs (candidates.py attack-zars) izmesti 2026-07-29 — sk. CHANGELOG § Politracker tīrīšana. Numurs saglabāts, lai #2–#6 atsauces citur nesabruktu. (Strikti validētie Pydantic modeļi joprojām dzīvo `src/models.py` — `AnalysisResult`/`Claim`/`Contradiction`/`ContextNote`.)

2. **Claims without `source_url` are dropped** in `save_analysis()` validation (`analyze.py`), not "at the DB layer": the source document's URL is authoritative, so a claim whose document has no `source_url` is recorded as a `missing_source_url` entry in the returned `failures` list (logged to stderr, not raised — easy to miss). `store_claim()` called directly will happily insert a NULL `source_url`. No URL = no provenance = can't cite, can't re-fetch, can't contradict. Locked by `tests/test_invariants.py::test_inv2_claim_without_source_url_dropped`.

3. **`store_claim()` is idempotent on `(opponent_id, source_url, topic)`.** Re-running the same triple returns the existing claim_id; first-write-wins. Bulk re-scrapes that revisit the same URL are safe. **Corollary (trap T2):** a document with several DISTINCT positions in one topic silently merges them into the first claim — differentiate topics or consolidate deliberately, and verify counts.

4. **`claim_type` values:** `'position'` (default, media/X rhetoric), `'saeima_vote'` (reserved for `@saeima-tracker`), `'commentary'` (third-party allegations with `speaker_id` set), `'program_promise'` (party election-program promises — see below). Readers filter by `claim_type`, not URL heuristics — **every render + brief query gates on `claim_type='position'`**, so non-`position` types are invisible to those surfaces by construction (this is what keeps program promises off politician pages / coverage / dashboards for free). See [CHANGELOG § claim_type split](wiki/CHANGELOG.md#2026-04-11--claim_type-split-position-vs-saeima_vote) + [§ Komentētāji speaker_id](wiki/CHANGELOG.md#2026-04-23--komentētāji-speaker_id-on-claims).

   4b. **A `saeima_vote` claim exists only for a CAST ballot** — `Par`, `Pret`, `Atturas`, `Nebalsoja`. Attendance states (`Reģistrējies` / `Nereģistrējies`) never become claims, whether as a whole procedural event or scattered inside a real vote. Code-enforced in `generate_claims_from_votes()` via `_BALLOT_VALUES_THAT_ARE_POSITIONS` + a motif-prefix early exit, locked by tests. Consequence you can rely on: a politician's `saeima_vote` claim count equals ballots cast, not sittings attended (before 2026-07-25 it did not — 30 476 attendance claims were cleaned out; the `saeima_votes`/`saeima_individual_votes` rows remain as the attendance record).

   4a. **`claims.party_id` (nullable FK→`parties`) + `claim_type='program_promise'` attribute a claim to a PARTY** (party election programs, 2026-07-02). `party_id` = the party; `opponent_id` = the party's list leader who carries the program (idempotency triple stays `(opponent_id, source_url, topic)`, so store **one consolidated promise per topic** per program source). Program promises render only in the party page's "Programma" section (`src/render/parties.py` filters `party_id=? AND claim_type='program_promise'`); excluded everywhere else by the `claim_type='position'` gate above. `NULL` for ordinary politician claims. Program docs ingest via `scripts/ingest_url.py`. Threaded through `db.store_claim`/`tools.store_claim`/`analyze.save_analysis` (`party_id=` kwarg). Rollback: `data/rollback_claims_party_id_2026-07-02.sql`.

5. **`claims.speaker_id` attributes authorship separately from subject.** `NULL` (or `= opponent_id`) = first-party: the politician IS the speaker. Non-NULL and `≠ opponent_id` = third-party commentary (historically `relationship_type='commentator'`; deprecated for new rows — see #11). Readers needing a concrete speaker should use `COALESCE(speaker_id, opponent_id)` (convention documented in `store_claim`'s docstring; new readers must follow it). [CHANGELOG § Komentētāji](wiki/CHANGELOG.md#2026-04-23--komentētāji-speaker_id-on-claims) + [`wiki/operations/agenti/claim-extractor.md`](wiki/operations/agenti/claim-extractor.md).

6. **`claims.document_id` is `Optional`.** `claim_type='saeima_vote'` claims store NULL (vote provenance via `saeima_individual_votes.politician_id` (=`opponent_id`) → parent `saeima_votes.url` (=`source_url`) / `saeima_votes.vote_date` (=`stated_at`)); `position` and `commentary` REQUIRE `document_id NOT NULL`. `documents.platform='saeima'` rows should not be created (convention, not code-enforced). [CHANGELOG § Strukturālā sanācija](wiki/CHANGELOG.md#2026-04-25--strukturālā-sanācija-pub_at-meta-tag-fix--saeima-vote-as-document-anti-pattern-noņemšana).

## Pipeline Invariants

7. **Contradiction check is mandatory.** For every new claim, compare against the full history for that politician (`search_similar_claims` with directional `claim_type_filter`). Store via `store_contradiction()`. Type values live in the `contradictions.severity` column: `direct_contradiction`, `reversal`, `minor_shift` (there is no separate `contradiction_type` column). Also check rhetoric-vs-action. `speaker_scope` defaults to `'first_party'`; pass `'commentary'` for commentator-self-consistency or `'all'` for legacy behavior. [CHANGELOG § Komentētāji](wiki/CHANGELOG.md#2026-04-23--komentētāji-speaker_id-on-claims).

8. **Context notes (`note_type='context'`) are append-only — add new rows, never overwrite.** Check existing notes before adding to avoid duplicate tendences. Overwriting destroys the evolution-over-time signal tendences exist to preserve. (`daily_brief`/`weekly_brief` rows in the same table are the deliberate exception — UPSERT-refreshed on same-day re-runs.)

9. **`save_analysis()` is atomic.** Analysis + claims + reviewed-docs update run in one SQLite transaction. Catastrophic DB failures return `status="failed"` with `transaction_rolled_back` and persist nothing. Validation-level skips return `status="partial"` without rollback — three causes: `missing_source_url`, inactive politician, and `silent_dedup` (an in-call idempotency collapse, see T2).

## Coalition Classification

10. **Truth source is `parties.coalition_status`.** Read via `src.coalition.get_coalition_map(db)` (batch) or `party_status(party)` (single). **Never** use `tracked_politicians.relationship_type` for coalition logic — it's a legacy per-politician tracking role.

- **`tracked_politicians.party` must be stored consistently within a single party** — full name is the norm (`MMN`/`JKP` are the short-name exceptions). Rendering resolves both forms, but string-grouping (the brief coalition/opposition table, wiki party counts) breaks on a mix — e.g. `ASL` + `Austošā Saule Latvijai` were counted as two parties until unified 2026-06-05 (rollback `data/rollback_party_label_hygiene_2026-06-05.sql`).

## Source-specific invariants (social · bills · video)

11. **`social_accounts` is X-only, one row per politician** (UNIQUE `(opponent_id, platform, handle)`; FB/website → `external_profiles`). **`feed_type` ∈ {`first_party`, `relay`}** controls `_store_tweets` linking: first_party requires per-tweet author handle match for `role='subject'`; relay defers to text-scanned mentions via `link_politicians_to_documents` (matches RSS flow). **`relationship_type='commentator'` is deprecated for new entries** — historical commentary claims with `speaker_id` FK remain as audit trail. **Journalists (`relationship_type='journalist'`) get `feed_type='relay'` by default** (operator decision 2026-08-21): their feeds stay discovery channels (text-scanned mentions link the politicians they cite), but they stop generating own `position` claims. Deliberate first_party exceptions (political strategists/analysts like Liepnieks, Rajevskis; journalist-candidates like Seržants) are operator calls — see [wiki/operations/seeding.md](wiki/operations/seeding.md) § Žurnālisti. [CHANGELOG § feed_type](wiki/CHANGELOG.md#2026-04-23--social_accountsfeed_type-relay-vs-first_party) + [§ Commentator demotion](wiki/CHANGELOG.md#2026-04-25--commentator-demotion--profila-x-subtaba).

12. **`saeima_votes.bill_id` and `saeima_bills.current_stage` are updated only via `append_bill_stage()`.** For NEW code, no other `UPDATE` to these fields is permitted. This protects denormalization sync — the vote→stage→bill timeline is atomic, and manual writes shred historical integrity. **Named historical exception (operatora lēmums 2026-08-17):** `scripts/backfill_saeima_bills.py` un `scripts/_apply_session_summaries_2026_05.py` rakstīja šos laukus vienreizējā vēsturiskajā backfill un paliek repo kā dokumentēta vēsture — tie NAV paraugs jaunam kodam.

13. **`platform='video'` documents store full speaker-labelled transcripts.** Content is `[mm:ss] @handle: text` lines. `claim_type` stays `'position'`; per-claim `source_url` carries a timestamp anchor (`?t=N` YouTube, `#t=N` elsewhere), which preserves `store_claim()` idempotence on the `(opponent_id, source_url, topic)` tuple. Extraction runs through `@video-extractor` per-speaker pass (not `@claim-extractor`). See [wiki/operations/agenti/video-extractor.md](wiki/operations/agenti/video-extractor.md). Operational since 2026-07-22; known limit: diarization speaker boundaries bleed on heated crosstalk — prefer calm interviews; the extractor's attribution stop-gate catches bad cases (BACKLOG § Video ingest).

## Output Conventions

- **UI language is Latvian throughout.** Claims = Pozīcijas, Contradictions = Pretrunas, Patterns = Tendences.
- **Timestamps use `now_lv()` from `src/db.py`** (Latvia UTC+3 / EEST).
- **Topic names use 33 canonical groups** from `src/topic_map.py` (33. — `NVO un pilsoniskā sabiedrība`, 2026-08-06). `store_claim()` / `store_contradiction()` auto-normalize; unknown topics pass through.
- **`sentiment=0.0`** on `save_analysis()` — the parameter exists only for schema compatibility; sentiment analysis was removed as unreliable. Never compute it, never store a non-zero value, never build features on it.
- **Grammar + stylistics gate (LV).** Before `store_*()`, commit, wiki sync, or publish, check every new Latvian string (claims, contradictions, syntheses, briefs, social drafts, UI text) for grammar (locījumi, garumzīmes, verb forms) AND stylistics (clear flow, no calques/invented words, "Dienas pārskats" not "brief"). This is Claude's responsibility before the tool call, not the operator's — if unsure a form is correct, rephrase. **Exception: `claims.quote` is VERBATIM** — a politician's own typos stay ("Steidamas", Kulbergs 2026-06-11; operator decision 2026-07-07). Correcting a quote is misquoting; the gate applies to OUR words (stance, reasoning, summary), never to cited ones.
- **No inline JavaScript on any public page — strict CSP.** The live site serves `script-src` WITHOUT `'unsafe-inline'` (`assets/htaccess.template`): browsers silently kill every `<script>` lacking `src=` and every `on*=` attribute, including ones injected via innerHTML. All executable JS lives in `assets/*.js` (auto-cache-busted — `_resolve_assets_version()` globs the dir); per-page data goes in non-executable `<script type="application/json" id="…">` blocks or `data-*` attributes; handlers are `data-*` + delegation. Locked by `tests/test_no_inline_js.py`. A new EXTERNAL script/style/font/connect host must be added to the CSP allowlist in `htaccess.template` or the resource silently fails on the live site (local preview won't catch it). Never re-add `'unsafe-inline'` to script-src. [CHANGELOG § Stingrā CSP](wiki/CHANGELOG.md#2026-07-23--stingrā-csp-drošības-galvenes--viss-inline-js-uz-assetsjs). UI patterns: [wiki/operations/ui-conventions.md](wiki/operations/ui-conventions.md).

## Known Traps (named failure modes → the rule that prevents each)

Each of these has bitten this project at least once; several recur monthly. History + rationale: `wiki/CHANGELOG.md`, open instances: `BACKLOG.md`.

- **T1 — Bare-surname / substring match.** The matcher links a namesake, geonym, or word-substring ("Kolu"→"Kolumbija"). *Rule:* substring matcher, no diacritic folding — if the person in the text isn't clearly the tracked politician, mark the doc empty and log the collision for operator review; `negative_patterns` fixes are operator-approved, never auto-added.
- **T2 — Idempotency merge.** Distinct same-topic positions from one document collapse into one claim. Within a single `save_analysis()` call this is now REPORTED (`silent_dedup` in `failures`, `status="partial"`); a collision with a claim stored in an earlier call is still silent. *Rule:* Data Contract #3 corollary — read `failures`, differentiate topics or consolidate deliberately, and verify stored-count == intended-count.
- **T3 — `source_url` drop misread as success.** Dropped claims surface only in the returned `failures` (stderr). *Rule:* read `failures`; every `missing_source_url` is a real loss to resolve.
- **T4 — Stripped-diacritic Latvian (context drift).** *Rule:* if diacritic validation (`src/quality.py`) trips mid-session, STOP and start a fresh session — drift is autoregressive. Parallel subagents get clean contexts.
- **T5 — `empty_doc_ids` omitted.** Zero-claim docs keep `reviewed_at IS NULL` and re-enter the backlog forever. *Rule:* `empty_doc_ids` is mandatory whenever a reviewed doc yields no claims.
- **T6 — Stale party/role after a public switch.** A claim says "leaving party X"; `tracked_politicians.party` still says X → blocs misclassify. *Rule:* verify + manual UPDATE (+ paired rollback) in the same routine; check role chronology (vote gaps!) before assuming a data bug. A party can also be wrong from seeding day with no claim to trigger on — the cheap cross-check is `saeima_individual_votes.faction` (`/audit-integrity` check 9), read as **coverage inside the sitting window**: 65 of 70 votes = truth, 17 of 70 = scraper artifact (Šmits, 2026-07-26). **Corollary — party ≠ faction, two different facts.** `party` is membership; `faction` is who sat in the faction FOR THAT VOTE (a member can sit outside: Kiršteins, LPV, `faction=NULL` — legitimate, do NOT "fix"). For any per-vote statement ("faction X split"), the authority is the `faction` distribution in THAT `vote_id`, never a `party` grouping — grouping by `party` manufactured a fake LPV split in note #373 (2026-07-26).
- **T7 — Brief skeleton coverage gap.** FIXED 2026-07-24: full sections = top-5 + every cnt≥3 topic; the remainder lands in the `### Pārējās tēmas` table — nothing disappears by construction. *Rule:* the Pārējās table is the honesty guarantee — brief-writer may PROMOTE a row into a full section, never silently delete one; a missing table on a multi-topic day = skeleton bug (STOP, report). [CHANGELOG § T7 slēgts](wiki/CHANGELOG.md#2026-07-24--t7-slēgts-brief-skelets-vairs-klusi-nemet-tēmas-pārējās-tēmas-tabula).
- **T8 — Saeima "0 votes" read as an empty day.** THREE vote-URL patterns exist (static `?OpenDocument` + JS `addVotesLink` + `./Voting?ReadForm&parentID={GUID}` since 2026-06-11); titania re-archives under new UNIDs. *Rule:* scrape ALL THREE, take the union — never re-derive the count from memory, the canonical regexes + union helper live in `scripts/p3_backfill_year_urllib.py::_extract_vote_urls_from_agenda` and the procedure in `.claude/agents/saeima-tracker.md` Step 2.B; 0 votes at a session with agenda items = STOP and report; completeness by `(vote_date, vote_time)`, never URL.
- **T9 — Rhetoric-vs-vote via embeddings.** Vote claims ARE vectorized, but semantic similarity does not surface rhetoric↔vote STANCE mismatches, and `claim_type_filter` (T10) excludes them from rhetoric searches anyway. *Rule:* an embedding search can never clear rhetoric-vs-vote; only `@contradiction-hunter`'s structural SQL pass (+ mandatory faction check) finds vote mismatches.
- **T10 — Cross-type embedding comparison.** *Rule:* always pass `['position']` for rhetoric-vs-rhetoric. All three filters are pushed INSIDE the k-NN query via a `claim_id IN (subquery)` constraint (`src/db.py::search_similar_claims`, corrected 2026-08-09); `top_k` is a budget within the politician's own filtered claims — the old `top_k=400` inflation workaround is obsolete.
- **T11 — "Optional-looking" step skipped under batch load** → required fields end up NULL. *Rule:* no optional substeps — atomic units (capture → summarize → store), no deferred batching, final gate hard-fails on NULLs.
- **T12 — Upstream format change misdiagnosed as removal** (X, VID, and saeima.lv have all done it). *Rule:* assume format change; check the upstream tracker; keep fallbacks; alert+retry, not hard failure.
- **T13 — Homonym contamination in bulk per-person ingest.** *Rule:* disambiguation whitelists (`vad_disambig` / `negative_patterns`) + a pre-publish audit of each new cohort.
- **T14 — Procedural vote quoted as a policy position.** One bill generates a chain of votes (agenda motions, committee referrals, urgency), and a faction routinely splits ACROSS that chain for reasons of process, not substance. Reference case 2025-04-10: Progresīvie abstained on the agenda motion and **one minute later voted PAR sending the same project to committee** — quoting only the abstention inverts the record. *Rule:* before citing any single vote as a position, pull every vote sharing that `document_nr` and read the chain; if the chain is mixed, cite the chain or cite nothing. A coalition-wide abstention is a fact about coalition procedure, not one party — check whether the other coalition factions did the same. Pairs with T9 and the abstention rule under Working Conventions.
- **T15 — Deploy pārnes VISU build koku, arī nepublicētus pārskata melnrakstus.** `scripts/deploy.sh` rsynco visu `output/atmina/`, un `check.sh` pilnais renders ģenerē arī melnraksta pārskata lapas; attēlu `approved=0` vārti noņem tikai hero — pati lapa renderējas (2026-08-09 tas aizbrauca live reāli). *Rule:* pirms jebkura deploy pārbaudi, vai `output/atmina/blog/` nesatur pārskata lapu, kuras vārti nav iziēti; "šaurs" iepriekšējais renders NESARGĀ, ja `check.sh` ir pārrenderējis visu koku. **Koda vārts kopš 2026-08-09:** `deploy.sh` preflight izsauc `check_output.py --publish-gate-only` (brief lapa bez `approved=1` attēla vai orfāna = exit 1; `--no-output-check` ir apzināta apiešana). **v2 kopš 2026-08-18:** papildus obligāta EKSPLICĪTA atļauja — `publish_approvals` rinda ar lapas slugu (`scripts/approve_publish.py <YYYY-MM-DD|nedela-YYYY-MM-DD>`); abi vārti ir UN (attēls = hero eksistē; atļauja = teksts drīkst iet ārā). Atslēga ir slugs, ne datums — dienas un nedēļas pārskatam var būt viens subjekta datums.

## When Uncertain — Escalation Rules

1. **Attribution uncertain** (is this text really about the tracked politician?) → return empty, log the collision candidate for operator review. Never guess-link; never auto-add `negative_patterns`.
2. **Claim confidence 0.5–0.6 or weak context** → store it, and mark the doubt by prefixing `reasoning` with `NEEDS_REVIEW: `. **<0.5** → same, plus say why in the same line. Never silently drop; never inflate confidence to clear a bar. You still write the marker into the `reasoning` TEXT — and `save_analysis()` also prepends it automatically when the reasoning admits an indirect reference (`tests/test_analyze.py::TestIndirectReferenceGate::test_save_analysis_appends_needs_review`). There is **no `needs_review` parameter**; an extra key in the claim dict is silently discarded, so a claim "flagged" that way reaches the DB looking fully confident.

   **Readers must query `claims.review_status`, never the text** (since 2026-08-03). It is a DERIVED column — two triggers maintain `'needs_review' | 'reviewed' | NULL` from the `reasoning` prose, so ad-hoc triage SQL cannot desynchronise it. **Never write the column by hand**; write the marker and let the trigger classify. Resolution means REPLACING the marker with `Izvērtēts YYYY-MM-DD:` (`wiki/operations/weekly-routine.md`); the column follows automatically. Marker form is cosmetic since 2026-08-04 (`Izvērtēts`, `REVIEWED`, `IZSKATĪTS` all derive to `reviewed`); the uppercase-only match is deliberate — SQLite `LIKE` folds case for ASCII only, so prose "izskatīts" never resolves a row — do not "fix" the pattern to lowercase.
3. **Contradiction plausible but unverified** → send to `@devils-advocate`; store survivors `confirmed=0`. Never auto-confirm. Zero yield is a valid outcome (~1 publishable per ~2700 raw pairs) — do not manufacture findings.
4. **Diacritic validation trips / suspected context drift** → STOP the session immediately, start fresh (T4).
5. **Scraper returns 0 or breaks** → treat as pattern error, not empty result (T8, T12). STOP + report rather than recording an empty day.
6. **Unsure a Latvian form is correct** → rephrase into a form you are certain of. Guessing grammar is not allowed past the gate.
7. **Anything outward-facing** (brief, social post, deploy, public-repo change) → proofread, confirm assets, ask the operator first. One approval ≠ standing approval.
8. **Any data mutation by hand** → paired `data/rollback_*.sql` in the same commit BEFORE applying. **Parallel agents each get a UNIQUE rollback filename (scope suffix)** — a shared rollback path silently destroys the safety net (2026-08-03: four agents overwrote one file). If the mutation touches `claims.topic` or `claims.stance`, **re-embed the row too** (`scripts/reembed_claims.py`, `--ids-from` for bulk; **not for `saeima_vote` rows — they carry no vector by design since 2026-08-21, and running the tool on one would resurrect it**) — `store_claim()` embeds `f"{topic}: {stance}"`, so a bare `UPDATE` leaves `claim_vectors` holding a vector built from the old text; nothing raises, `search_similar_claims` just quietly ranks by what the claim used to say.

   **And `topic` is part of the idempotency key, so an `UPDATE claims SET topic` can MANUFACTURE duplicates.** Before any such migration, run the collision query — would the new value land a row on an existing `(opponent_id, source_url, topic)` triple? If yes, the dedup decision belongs in the same script (this happened twice; 4 087 duplicate rows took until 2026-08-02 to clear). Corollary for bulk loads: idempotency is not stable across code changes, because `topic` is derived by `_motif_to_topic()`, which evolves — safety comes from the loader's own `(vote_date, vote_time)` check, never from `store_claim()`. Never run a topic migration over votes inside a pending load's scope. `/audit-integrity` checks 11 + 14 are the after-the-fact detectors.
9. **Denormalized field might be stale** (party/role/topic) → verify against the truth source (`parties.coalition_status`, `votes.topic`, role chronology) before trusting or citing it.
10. **A decision future sessions must honor** → write it into this file / wiki / agent prompt, not private memory.

Meta-rule: prefer the branch that stops-and-surfaces over the branch that writes.

## Schema invariants (load-bearing)

- `opponent_id` references `tracked_politicians.id` on claims, analyses, contradictions, context_notes, social_accounts, logs. Documents use `document_politicians` junction table (many-to-many with roles: subject, mentioned, mention_target).
- `relationship_type='inactive'` hides politicians from dashboard.
- **The matcher is substring-based and does NOT fold diacritics.** A politician with a diacritic surname (Pūce, Kļaviņš, Vītols, Šuvajevs) needs BOTH diacritic and ASCII variants in `name_forms` — sources that strip diacritics (X, RSS, scraped HTML) otherwise never link. Since 2026-07-27 (B2+D2+H, [CHANGELOG § Matcher B2+D2+H](wiki/CHANGELOG.md#2026-07-27--matcher-b2d2h-vārda-robežas-paplašinātais-priekšvārda-veto-handle-formas)): single-word forms match only at word boundaries, the foreign-first-name veto covers any match count, and registered @handles (`social_accounts` ∪ `x_handle`) are match forms — a missing `social_accounts` row now also costs tweet-mention coverage. Regression harness: `scripts/eval_matcher_collisions.py` (gates FP≤3, gold≥1260). Audit with `scripts/audit_matcher_name_forms.py`; seeding pattern in [seeding.md](wiki/operations/seeding.md). Pairs with the `-ņš`/`-iņa` cross-gender collision caution in `src/matcher.py::_latvian_surname_inflections`.
- **Timestamp columns are NOT one convention — check before you filter by date.** `claims`, `context_notes`, `documents`, `contradictions` store **LV** time (`now_lv()`); `political_tensions.created_at` and `analyses.created_at` store **UTC** (`DEFAULT CURRENT_TIMESTAMP`). So a UTC column needs `DATE(created_at, 'localtime') = ?` and an LV column must NOT get that modifier — either mistake shifts rows by a day in the 21:00–23:59 UTC window, exactly when the evening routine runs. Both directions have shipped as live bugs (2026-07-29, [CHANGELOG § UTC lasījumi](wiki/CHANGELOG.md)). Locked by `tests/test_briefs.py::TestTensionDayBoundaryTimezone` (UTC side) and `tests/test_routine.py::TestEveningBoundaryTimezone` (LV side). Convention documented per-column in `src/schema.sql`. Corollary: **never "fix" a timestamp by writing `now_lv()` into a UTC column** — that is the defect, not the repair.
- **`documents.scraped_at` is MUTABLE for `platform='web'` — a past day's document count can go DOWN.** URL-first dedup (`src/db.py`) treats the URL as canonical: when a publisher edits an article between fetches, the row is UPDATEd in place and `scraped_at` resets to now — the document moves out of its original day's bucket. Expect rather than investigate: a re-ingest can shrink yesterday's `DATE(scraped_at)` count, and the ingest's "N docs" summary counts in-place updates alongside genuine inserts. Only `web` rows do this.

  **The heavier consequence: claims and junction rows can outlive the text they cite.** When a publisher puts a *different story* behind the same URL, the UPDATE overwrites `content` while `COALESCE` keeps the old `title`, and every claim, quote and junction row extracted from that document now points at text that no longer exists; `reviewed_at` is not reset, so the new story never re-enters the queue. Reference: doc 72446 (2026-08-06) — `scraped_at` > `reviewed_at` is the signature. Treat a `title` that disagrees with the first content line as this class until proven otherwise. **Kopš 2026-08-18 UPDATE zars pats sedz šo klasi:** `title` pārrakstās ar jauno (`COALESCE(?, title)` — vecais paliek tikai tad, ja fetchs virsrakstu nenes), un `reviewed_at` tiek atiestatīts uz NULL, tāpēc dokuments ar nomainītu saturu atgriežas ekstrakcijas rindā. Identisks re-fetch to NEizraisa — tas apstājas pie `content_hash` dedup un līdz UPDATE nenonāk, tātad review zīmogi no atkārtotiem skrāpējumiem nedeg. Vēsturiskie kandidāti (doc 72446 klase) NAV atpakaļejoši laboti — operatora triāža.
- **`documents.reviewed_at` is per-DOCUMENT, not per-politician.** A document reviewed in one politician's extraction slot is stamped for everyone: a second tracked politician named in the same text looks processed while nothing was ever extracted for them, and no queue re-offers it. This is what let the junction role-inversion class hide (a `mentioned` speaker never enters `get_pending_politicians`, which walks `role='subject'`). When you review a multi-politician document, say which politician the stamp covers.
- **A brief's identity is its SUBJECT date, never `created_at`.** The routine day a brief covers lives in `context_notes.topic` (`dienas analīze YYYY-MM-DD`) and its H1; `created_at` is merely when it was stored, and the evening routine regularly stores after midnight. Read it with `src.briefs.brief_subject_date()` (topic → H1 → `created_at` for legacy rows only), which `src/render/blog.py` slugs and `src/routine.py` steps 7/8 share. Keying off `created_at` once reported a nonexistent brief as present (2026-07-29 false green). Locked by `tests/test_routine.py::TestBriefIdentityIsSubjectDate`.
- **`tracked_politicians.x_handle` (legacy column) ≠ `social_accounts.handle`.** `x_handle` drives the profile's X-link in render; `social_accounts.handle` is authoritative for the X fetch. They can silently diverge (id=19 Ašeradens once held `'VDombrovskis'`) — verify `x_handle` when seeding or auditing a profile.
- **From now on, every hand-run data migration (`data/*.sql` or a `scripts/fix_*.py` that mutates rows) ships a paired `data/rollback_*.sql` committed alongside it.** A rollback that lives only in the working tree is one `git clean` away from gone — and with it the only path back from a bad reattribution. Header each rollback with the forward change it reverses + the apply date. (Pre-2026-06-08 `fix_*.py` without a rollback are acknowledged debt, not a model to copy.)
